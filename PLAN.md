# PLAN.md — анализатор переговоров

## Архитектура

SvelteKit + Bun. Одна страница: слева список стенограмм-примеров, справа текст и результат в виде pretty-JSON.

AI/API: **OpenRouter SDK**, модель **`nvidia/nemotron-3-ultra-550b-a55b:free`** (задаётся через env-переменные).

Поток запроса:

```
выбор стенограммы → GET /api/transcripts/[slug] (превью)
                  → POST /api/analyze
                        валидация входа (Zod)
                        → LLM (промпт + текст + дата разговора; response_format: json_schema)
                        → валидация ответа (Zod)
                  → JSON { analysis }
```

Серверная логика — `src/lib/server/`:

- `llm/` — адаптер LLM: интерфейс + типы ошибок (`adapter.ts`), реализация OpenRouter (`openrouter.ts`), чтение ключа/модели из `$env/static/private` (`index.ts`).
- `prompts.ts` — системный промпт экстрактора (только факты из текста, всё на русском, цитаты-доказательства, явные неопределённости).
- `schema.ts` — схема `TranscriptAnalysis` (Zod) для валидации и JSON Schema для structured output.
- `transcripts.ts` — встраивает `transcripts/*.txt` в сборку (без чтения с диска), парсит дату/участников/превью.

Маршруты: `POST /api/analyze`, `GET /api/transcripts`, `GET /api/transcripts/[slug]`.
UI-компоненты: `TranscriptPicker`, `TranscriptPreview`.

## Что проверено

- Сквозной анализ реальной стенограммы: возвращается структурированный JSON на русском, `200`.
- Встречи: дата/время/часовой пояс/цель, включая разрешение относительных дат по дате разговора.
- Сроки: raw-формулировки сохраняются (`до среды`), календарная дата резолвится.
- Условные договорённости (`если… подтвердит…`) помечаются как условия, а не как соглашения.
- Неоднозначности выносятся в `uncertainties` (дата, часовой пояс, роли).
- Ошибки: неверный ввод → 400, не настроен ключ → 500, провайдер/невалидный ответ → 502, с понятным сообщением.
- Сборка и линт чистые (check / lint / build — 0 ошибок).

**Стенограммы-фикстуры** (`transcripts/`) покрывают: техвстреча с предусловиями, условный пилот, сроки менеджера, бюджет и роли утверждения, безопасность/облака/NDA, «не звонить без меня», отложенная миграция, неоднозначные даты.

## Ограничения / где ошибается

- Ответ модели может быть нестабильным: изредка английский вместо русского, неверная классификация интента, «додумывание» деталей при слабой формулировке.
- «До среды», смещения часовых поясов и IANA-зона — предположения, помечаются как неопределённости.
- Грань «условие против обещания» и роли (чей генеральный) зависят от формулировки.
- Без проверки человеком: ошибки модели попадают в вывод как есть.
- Работает только при заданных env-переменных (локально `.env.local`, на Vercel — Environment Variables).

## Следующая итерация

- Уверенность по полям и подсветка фрагментов-источников в тексте.
- Пакетный анализ и сохранение результатов; проверка/редактирование человеком перед CRM.
- Экспорт в форматы CRM; аналитика повторяющихся возражений и рисков.
- Оценочный набор: фикстуры + эталонный JSON + регрессионные тесты (русскоязычность, отсутствие выдуманных фактов).
- Прогресс/стриминг ответа и отмена запроса в UI.
